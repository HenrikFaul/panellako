## Összefoglaló

Initiative #5 (Multi-Building Dashboard + Building Picker) implementálása. Az alkalmazás mostantól támogatja a multi-épület kezelést: egy felhasználó több épület kezelőjét érheti el egyetlen bejelentkezéssel. A `/app` route egy building picker oldalt mutat, a `/w/[buildingId]` route az adott épület dashboard-ját.

## Routing séma

```
/            → Legacy dashboard (nem scoped, mock-compatible)
/app         → Building Picker (auth required)
/w/[uuid]    → Building Dashboard (auth + membership required)
/auth/signout → POST sign-out handler
/login       → Login oldal (authenticated user → redirect /app)
```

## Adatarchitektúra

1. `get_my_buildings()` RPC — épület aggregátumok per felhasználó (building_id, name, address, role, unit_count, open_tickets)
2. `validate_building_membership(_building_id)` RPC — membership check, role, unit_id visszaadása
3. `getDashboardData(role, buildingId?)` — minden lekérdezés building-scoped ha buildingId meg van adva

## Middleware védelemstratégia

| Útvonal | Nem hitelesített | Hitelesített |
|---------|-----------------|--------------|
| `/app` | `→ /login?next=/app` | ✓ picker |
| `/w/[id]` | `→ /login?next=/w/[id]` | membership check |
| `/login` | ✓ | `→ /app` |
| `/` | ✓ | ✓ (legacy) |

## Back button compliance

- Building picker → épület dashboard: `<Link href="/w/[id]">` — history push, Back → picker
- Épület dashboard → picker: `<Link href="/app">` — history push, Back → dashboard
- iOS: hash-alapú section navigáció a dashboardon belül (anchor linkek)
