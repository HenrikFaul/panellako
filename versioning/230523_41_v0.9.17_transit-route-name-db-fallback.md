# v0.9.17 — Transit map: DB fallback for vehicle route name resolution

**Dátum:** 2026-05-23
**Branch:** claude/fix-cron-null-values-uDCqd

## Probléma

A tömegközlekedés térképen a járatok belső GTFS ID-kat mutattak (`3010`, `4750`, `1200`, `320` stb.) a nyilvános BKK járatnevek (`30`, `47`, `M4`, `75` stb.) helyett.

**Gyökérok:** Az `ensureRouteInfoMap()` függvény a BKK OBA REST API-tól függött (`futar.bkk.hu/routes-for-agency`). Ha ez az API nem elérhető (pl. `BKKFUTAR_API_KEY` nincs beállítva, Vercel IP-ről rate limit, vagy hálózati hiba), az útvonaltérkép üres marad. Ekkor a GTFS-RT feed belső route_id értékei (`BKK_3010` → normalizált: `3010`) kerülnek a térképikonokra.

## Fix

`app/api/transit/vehicles/route.ts`:
1. `createDbClient()` segédfüggvény hozzáadva — `NEXT_PUBLIC_SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` (vagy anon key) alapján hoz létre Supabase klienst
2. `ensureRouteInfoMap()` végén DB fallback: ha az OBA API fetch sikertelen/üres, a `transit_routes` tábla adja a route_id → short_name mappinget
3. Azonos map-felépítési logika: minden route-hoz 2-3 kulcs (pl. `BKK_3010`, `3010`, és leading-zeros-nélküli forma)

## Miért működik

A `transit_routes` táblát a szinkron cron (`/api/transit/sync?action=stops-routes`) tölti fel a `stops-for-location.json` BKK OBA végpontból — ugyanaz az adatforrás, de offline módon, cron job-ként. Így a DB tartalmaz helyes `short_name` értékeket, és az élő vehicles endpoint akkor is fel tudja oldani a route neveket, ha az OBA API éppen nem elérhető.
