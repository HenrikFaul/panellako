# v0.6.4 — Transit null name + departures ID normalizálás + kornyezet crash

**Dátum:** 2026-05-19
**Ág:** claude/fix-cron-null-values-uDCqd
**Típus:** bugfix (3 egymástól független produkciós hiba)

## Összefoglalás

Három egymástól független produkciós hiba javítása, melyek mindegyike a cloud environment network policy (korlátozott kimenő hálózat) és a GTFS–Futár ID-formátum eltérésből eredt.

## Gyökérokok és javítások

### 1. `gtfs_derive_refs` — null name constraint violation

**Tünet:** `null value in column "name" of relation "transit_stops" violates not-null constraint`

**Gyökérok:** A `gtfs_derive_refs` job a `transit_stop_routes` tábla összes `stop_id`-jára számított `route_refs`-t, majd ezeket upsert-elte a `transit_stops`-ba (`onConflict: 'stop_id'`). Ha egy `stop_id` nem létezett a `transit_stops`-ban (orphaned stop_route sor), a Supabase INSERT-et próbált `name` nélkül → NOT NULL violation.

**Javítás:** A upsert előtt pre-fetch-eli a meglévő `stop_id`-kat chunkonként (500/batch), és csak azokat frissíti amelyek már léteznek. Az orphanedCount a result objektumban látható a diagnosztikához.

### 2. Transit departures — „API nem elérhető" badge GTFS stop ID-knál

**Tünet:** `Megálló ID nem BKK formátum: "F00048"` warning, 0 járat megjelenítés, „API nem elérhető" badge

**Gyökérok:** A GTFS `stops.txt` import `F00048` formátumú stop_id-kat tárol (BKK_ prefix nélkül). A departures route-ban a `if (!stopId.startsWith('BKK_'))` feltétel minden ilyen megállóra mock departures-t adott vissza anélkül hogy a Futár API-t megpróbálta volna.

**Javítás:** Az API route most normalizálja az ID-t: ha `/^[A-Z]\d/` mintára illeszkedik (BKK GTFS formátum), automatikusan `BKK_` prefixet kap. Csak a teljesen inkompatibilis formátumok (pl. OSM node szám) kapnak továbbra is mock fallback-et.

### 3. /kornyezet kliens-oldali crash

**Tünet:** `Application error: a client-side exception has occurred`

**Gyökérok:** Az Open-Meteo API és az Overpass API egyaránt blokkolva van a cloud environment network policy-ja által. A weather route `{ error: "..." }` JSON-t adott vissza 502-vel; a kliens ezt `weather` state-be töltötte (truthy object), majd `weather.current.uvIndex` hozzáférésnél `TypeError`-t kapott (`current` undefined).

**Javítás:**
- weather route: mock fallback (válid `current` objektum) hiba esetén
- kliens: `weather?.current` guard a `setWeather` hívásnál
- doUrban: error JSON detektálás → `errorUrban=true` → retry UI
