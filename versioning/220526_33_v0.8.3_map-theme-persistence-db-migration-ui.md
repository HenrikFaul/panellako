## Probléma

1. A superadmin felületen beállított térképstílus oldalfrissítés után mindig visszaállt `dark`-ra.
2. A profil-cím betöltése nem működött (`user_reference_addresses` tábla hiánya).

## Gyökérok

### Térképstílus nem persistálódott — 3 hiba együttese

1. **`fetchMapTheme` catch ága** nem resetelte `fetchPromise = null`-ra, így az első sikertelen fetch után minden következő hívás ugyanazt a stale rejected Promise-t kapta vissza — az első oldalfrissítés után minden térkép örökre dark maradt.

2. **Optimista UI update** (`saveMapTheme` a `superadmin-client.tsx`-ben): `setMapTheme(id)` korábban a PATCH kérés előtt futott, elfedve az esetleges DB-írási hibákat. A user azt hitte, elmentett, pedig nem.

3. **Nincs localStorage fallback**: A hook minden oldalfrissítésnél újból a DB-ből töltötte a témát — ha a fetch lassú, a user pillanatnyi dark flash-t látott. Ha a fetch sikertelen, dark marad.

### DB migráció rossz projektre alkalmazva

A `user_reference_addresses` és `map_theme_default` migrációk a GeoData projektbe kerültek (`buuoyyfzincmbxafvihc`) a Panellako (`wzromwxpjlyrqbdiapep`) helyett.

## Javítások

### `hooks/use-map-theme.ts`
- `catch` ág: `fetchPromise = null` + `localStorage` fallback
- `useState` initializer: `cachedTheme ?? readLocalStorage() ?? getTheme(DEFAULT_THEME_ID)` — azonnal helyes téma DB nélkül
- `invalidateMapThemeCache(newThemeId?: MapThemeId)`: ID-t is fogad, azonnal írja a cache-t és localStorage-t

### `components/superadmin-client.tsx`
- `saveMapTheme()`: `setMapTheme(id)` és `invalidateMapThemeCache(id)` csak `res.ok` után fut
- Hibaüzenet részletes szöveg + 5s timeout
- Új „Migrációk alkalmazása" szekció: gomb + eredmény-lista + manuális SQL fallback

### `app/api/settings/map-theme/route.ts`
- `console.warn` hiányzó env var esetén
- `console.error` DB read error esetén
- Regex validáció: `/^(minimal|nature|dark|dlc)$/.test(id)`

### `app/api/superadmin/apply-migrations/route.ts` (új)
- POST endpoint, superadmin-auth protected
- Két módszerrel próbálja a DDL-t: `supabase.rpc('exec_sql')` → `fetch('/pg/query')`
- `manualSqlIfFailed` mező: nyers SQL ha mindkettő sikertelen
