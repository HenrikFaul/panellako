## Technikai döntések

### TypeScript konfiguráció
`erasableSyntaxOnly: true` megakadályozza a TypeScript `enum` és `namespace`
kulcsszavak használatát, amelyek az ES modulban nem törölhetők (v5.5+). A jelenlegi
kódbázisban ezek nem használatosak, így a flag azonnal érvényes. `noUnusedLocals` és
`noUnusedParameters` kötelezővé teszik a már meglévő code style-t — az előző PR-ban
tapasztalt `'_req' is defined but never used` Vercel build-hiba kategóriáját szüntetik meg.

### `satisfies` vs explicit type annotation
Az explicit annotáció (`const CFG: Record<K,V> = {...}`) a típust `Record<K,V>`-re
tágítja, ezért az értékek string literálra való szűkítése elvész. A `satisfies`
megtartja a literális típusokat (`'Közút L_den'` marad `string` helyett), miközben
a struct shape ellen ellenőriz. Visszafele kompatibilis: ha az objektum nem felel meg
a Record-nak, fordítási hiba.

### oklch
A teal brand palette (H≈181–188) és a slate surface tokenek (H≈247) oklch-ban
egységesen kezelhetők. Dark mode implementálásakor elegendő lesz csak az L (lightness)
értékeket megváltoztatni egy CSS media query-ben — a szín és chroma automatikusan
konzisztens marad az egész palettán.

### resolved_at szemantika
A `.governance/roles_permissions.md` dokumentálja: a `resolved_at` az első 'megoldva'
állapot időpontját rögzíti és **soha nem törlődik visszanyitáskor**. Ez a Supabase
trigger szinten nem kerül most kényszerítésre (túlkomplexitás lenne), de az API route
felelőssége a helyes beállítása (jövőbeli feladat).
