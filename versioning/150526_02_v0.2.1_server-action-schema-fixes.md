## Összefoglalás

A v0.2.0 sprint Server Action rétegében 3 sémaeltérés és 1 UX hiba volt azonosítva a doc creation toolkit keresztreferencia-elemzése által. Ez a release mind a négyet javítja.

---

## Javított hibák

### 1. `document_acknowledgements` oszlopnév eltérés (High)
- **Fájl:** `app/actions/documents.ts`
- **Probléma:** `acknowledgeDocument()` `acknowledged_at` mezőt küldött, de a séma (`supabase/schema.sql` line 139) `viewed_at`-et definiál. Az upsert silently misfired.
- **Javítás:** `acknowledged_at` → `viewed_at`

### 2. `meter_readings.submitted_at` nem létező mező (Medium)
- **Fájl:** `app/actions/meter-readings.ts`
- **Probléma:** `submitMeterReading()` `submitted_at: new Date().toISOString()` mezőt insertált, ami nem szerepel a sémában. A `created_at` oszlop `default now()` értékkel kezeli az időbélyeget.
- **Javítás:** `submitted_at` mező eltávolítva az insertből.

### 3. `documents.uploaded_by` nem létező mező (Medium)
- **Fájl:** `app/actions/documents.ts`
- **Probléma:** `createDocument()` `uploaded_by: user.id` mezőt insertált, ami nem szerepel a `documents` sémában. Az `uploaded_at` default now()-val auto-set.
- **Javítás:** `uploaded_by` és `uploaded_at` mezők eltávolítva az insertből.

### 4. Optimista rollback hiánya (Medium)
- **Fájl:** `components/dashboard-client.tsx`
- **Probléma:** Ha a `createTicket` vagy `updateTicketStatus` Server Action sikertelen, az optimista UI-változás megmarad.
- **Javítás:**
  - `submitTicket`: rollback `setTickets((prev) => prev.filter((t) => t.id !== optimisticTicket.id))` a `result.success === false` ágban; form reset csak sikeres esetben fut.
  - `updateTicketStatus`: `previousTickets` snapshot megőrzése, `setTickets(previousTickets)` visszaállítás sikertelen Action esetén.
