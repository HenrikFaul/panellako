# v0.7.14 — Magyarország-szintű címkereső (Nominatim fallback) + profil-mentés + környezeti referencia-cím

**Branch:** `claude/cycling-routes-sources-sgeIO`
**Date:** 2026-05-20
**Type:** Feature (address search + persistence)

## Motiváció

A `Profil adatok és címkereső` szekció címkereső endpoint-ja (`/api/location/autocomplete`) eddig kizárólag a `osm_addresses` Supabase-táblát kereste, ami a production-ben jelenleg üres / nem létezik → **a UI semmilyen javaslatot nem adott** a Gidófalvy Lajos u. 9 vagy bármely más magyar címre. Emellett a "Profil mentése" gomb csak a komponens-statet váltotta (`profileSaved = true`), tényleges adatbázis-mentés nem történt.

A user explicit kérése: **MINIMÁLIS** megoldás, mert ezt a táblát hamarosan "egy jobb brutálabb táblára" fogja cserélni — így sok logikát ne építsünk rá.

## Mit változott

### 1) `app/api/location/autocomplete/route.ts` — Nominatim fallback
- Megőrizte a meglévő Supabase `osm_addresses` ranking-logikát (search-terms → ilike OR-filter → score-os rendezés)
- Ha a Supabase 0 eredményt ad / nem elérhető / RLS-hiba / schema-cache hiba → **automatikusan Nominatim-re esik vissza**
- `https://nominatim.openstreetmap.org/search?countrycodes=hu&format=jsonv2&addressdetails=1&limit=8`
- `User-Agent: panellako.hu/1.0 (info@panellako.hu)` (Nominatim usage policy)
- **1 req/sec/IP** throttle (in-memory Map)
- **24 h cache** (in-memory Map, max 500 bejegyzés)
- Csak ha `query.length >= 4` (a frontend 350 ms debounce-szal hív, így ~3 req/sec maximum)
- **Response shape megváltozott**: `suggestions` mostantól `AddressOption[]` (volt: `string[]`). Frontend backward-compat guard normalizál.
- `source: 'supabase' | 'nominatim'` mező minden javaslaton.

### 2) `supabase/migrations/20260521_user_reference_addresses.sql`
Új tábla — szándékosan minimális:

```sql
create table if not exists public.user_reference_addresses (
  user_id      uuid primary key references auth.users(id) on delete cascade,
  display_name text not null,
  lat          double precision not null,
  lon          double precision not null,
  street       text,
  house_number text,
  city         text,
  district     text,
  postcode     text,
  floor        text,   -- opcionális: emelet
  door         text,   -- opcionális: ajtó
  source       text not null default 'nominatim',
  updated_at   timestamptz not null default now()
);

alter table public.user_reference_addresses enable row level security;

create policy "Users can read own reference address"
  on public.user_reference_addresses for select using (auth.uid() = user_id);
create policy "Users can upsert own reference address"
  on public.user_reference_addresses for insert with check (auth.uid() = user_id);
create policy "Users can update own reference address"
  on public.user_reference_addresses for update using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

Tervezési döntések:
- **PK = user_id** (egy user, egy referencia-cím) — a user később mostohábbra cserélheti, addig nem szükséges több
- RLS védi (a user csak saját rekordját látja/írhatja)
- `floor`/`door` szándékosan külön a meglévő `units.unit_label`-től — a referencia-cím a környezeti job-okhoz (kerékpárút-távolság, levegő-stáció proximitás stb.) kell, nem az albetét-master-data-hoz

### 3) `app/api/user/reference-address/route.ts`
- `GET` → session user `user_reference_addresses` rekordja (vagy `null`)
- `POST` → upsert (`onConflict: 'user_id'`) — input validáció: `display_name`, `lat`, `lon` kötelező
- `auth.getUser()` a session-cookie-ból — nincs service_role write, RLS a single source of truth

### 4) `components/dashboard-client.tsx` Profil-szekció
- Új state: `selectedAddress: AddressOption | null`, `floor`, `door`, `addressSource`, `profileSaveError`
- A javaslat-lista mostantól `AddressOption[]`-ot iterál, soronként `source` badge (`GeoData` / `OSM`)
- Cím-kiválasztás után megjelennek az emelet/ajtó input-ok
- `onSubmit` async: ha van `selectedAddress`, POST-olja `/api/user/reference-address`-re (401-et csendben kezeli — demo módban nincs session)
- Zöld toast "Cím elmentve" (vagy "Profiladatok mentve"), 3 mp auto-hide

### 5) `app/w/[buildingId]/kornyezet/page.tsx` + `components/environment-page-client.tsx`
- A server component a building lat/lon helyett `user_reference_addresses.lat/lon`-t használ, ha van mentett rekord
- Új prop `usedReferenceAddress: boolean` jelzi a kliens-komponensben
- A kliens emerald banner-t jelenít meg ha igaz: "Az alábbi adatok az Ön referencia-címe alapján számítódnak: <displayName>"
- Az összes downstream API-call (environment/*, cycling, air-quality stb.) ezt a koordinátát kapja

## Feltételezések

- **A `currentDate: 2026-05-20` környezetben** a CHANGELOG-ot ezzel a dátummal jelöltem
- **Profile-card kontextus**: a meglévő `form onSubmit` csak `setProfileSaved(true)` volt. Ezt async-ra cseréltem, a meglévő név/lakás field-eket NEM bántottam (azokat egy másik agent fogja Supabase-elni, ha kell). Csak a kiválasztott címet mentem el — minimal scope, ahogy a user kérte.
- **A Hero agent egyidejűleg módosította a working dir-et** (CHANGELOG v0.7.15 + `dashboard-hero-scene.tsx`). Az ő munkája és az enyém **nem ütközik**: én a Profil-szekciót és az autocomplete endpoint-ot piszkáltam, ő a hero JSX-et és új komponenst hozott létre. Mind a kettő egy `dashboard-client.tsx`-en módosít, de különböző JSX-blokkokat — git merge konfliktus nem várható, de ha mégis, a Hero agent verziójának `import DashboardHeroScene` sora és az én `AddressOption` típusom egyaránt megtartandó.
- **Nem futtattam migrációt** — a user fogja `supabase db push` vagy az MCP `apply_migration` tool-on keresztül. A migráció idempotens (`if not exists` + `drop policy if exists`).
