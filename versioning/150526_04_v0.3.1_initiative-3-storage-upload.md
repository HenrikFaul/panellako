## Összefoglaló

Initiative #3 (Supabase Storage Document Upload) implementálása. A dokumentumtár mostantól valós fájlfeltöltést és biztonságos megnyitást támogat Supabase Storage alapon.

## Módosított fájlok

| Fájl | Módosítás |
|------|-----------|
| `app/actions/documents.ts` | `uploadDocument` + `getDocumentSignedUrl` Server Action hozzáadva |
| `components/dashboard-client.tsx` | Dokumentum feltöltési form, "Megnyitás" gomb signed URL-lel |
| `supabase/schema.sql` | `votes` tábla unique constraint (`resolution_id, voter_profile_id`) |

## Implementáció részletei

### uploadDocument Server Action
- Kötelező mezők: fájl, cím, kategória
- Engedélyezett MIME típusok: PDF, JPG, PNG, DOC, DOCX, XLS, XLSX
- Max fájlméret: 10 MB
- Storage path: `{building_id|global}/{timestamp}_{sanitized_filename}`
- Sikertelen DB insert esetén az uploadolt fájl visszatörlésre kerül (rollback)
- `file_url` oszlopba a storage path kerül (nem teljes URL)

### getDocumentSignedUrl Server Action
- 1 óra lejáratú signed URL generálás
- Legacy/mock http(s) URL-ek változatlanul visszakerülnek (backwards compat)

### Dashboard UI
- Manager szerepkör esetén "+ Feltöltés" gomb jelenik meg a dokumentum szekcióban
- Feltöltési form: cím (kötelező), kategória (kötelező), verzió, láthatóság, fájl
- Feltöltés állapotjelzés: feltöltés folyamatban → feltöltve / hiba üzenet
- "Megnyitás" gomb: minden dokumentumnál; signed URL-t kér le és új lapon nyit

### Votes unique constraint
- `ALTER TABLE votes ADD CONSTRAINT votes_resolution_voter_unique UNIQUE (resolution_id, voter_profile_id)`
- Szükséges a `submitVote` upsert `onConflict: 'resolution_id,voter_profile_id'` működéséhez

## Előfeltétel (manuális lépés)
A Supabase dashboardon létre kell hozni a `documents` nevű Storage bucketet. A Server Action a bucket meglétét feltételezi.
