# Marketing Value — v0.2.0 SSR Auth + Server Actions Sprint

**Feature name:** SSR Auth Hardening + Real Data Writes Sprint  
**Version:** v0.2.0  
**Date:** 2026-05-15

---

## 1. One-sentence user-language description

A PanelLakó-ban beküldött hibabejelentések, óraállások és értesítések mostantól valóban mentésre kerülnek — és a rendszer biztonságos szerver-oldali hitelesítéssel védi az épületi adatokat.

**EN:** Fault reports, meter readings, and announcements submitted in PanelLakó are now actually saved to the database — secured by server-verified authentication that protects sensitive building data.

---

## 2. Problem it replaces

- **Előtte:** A beküldött hibabejelentések csak az adott böngésző-munkamenetben maradtak meg — oldalfrissítés után eltűntek. A kezelők semmit nem kaptak.
- **Előtte:** Az auth-ellenőrzés kliens-oldali cache-ből olvasott, amelyet meghamisítani vagy lejárni lehetett anélkül, hogy a szerver észrevette volna.
- **Mostantól:** Minden adat szerver-oldali Server Action-ön keresztül kerül a Supabase adatbázisba, a hitelesítés szerver-ellenőrzött (`getUser()`), a munkamenet automatikusan frissül middleware-rel.

---

## 3. Primary beneficiary personas

- **Közös képviselő (building manager):** A beküldött hibajegyek és értesítések most valóban elmentésre kerülnek — reggel bejelentkezve meglátja, amit tegnap beküldtek a lakók.
- **Lakó (resident):** A beküldött hibabejelentés és mérőóra-állás megmarad a rendszerben, nem kell kétszer beküldeni.
- **Könyvelő / Bizottság:** A dokumentum-visszaigazolások rögzítve vannak, auditálható a folyamat.

---

## 4. Marketing-ready claim

> "A PanelLakó nem prototípus — hanem production-ready platform. Amit beküld, az megmarad. Amit a képviselő jóváhagy, azt az audit napló rögzíti."

**EN:**
> "PanelLakó isn't a prototype — it's a production-ready platform. What you submit stays saved. What the manager approves, the audit log records."
